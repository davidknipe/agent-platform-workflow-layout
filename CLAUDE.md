# agent-platform-workflow-layout

## What this is
A browser tool that fixes the canvas layout of Optimizely Opal workflow agents. It takes a pasted Opal workflow JSON export and returns the same JSON with `agent_metadata.nodes` and `agent_metadata.edges` rebuilt so the workflow renders cleanly in the Opal UI (no overlapping nodes, no tangled edges).

The layout engine is a standalone TypeScript module (`opal-workflow-layout.ts`) — the single source of truth. The browser tool (`index.html`) imports the compiled output. The module can also be used independently by other applications.

See `application.md` for the full specification: JSON schema, layout algorithm details, Axiom design system tokens, behavioural contract, security requirements, and known unknowns.

## Files
- `opal-workflow-layout.ts` — layout engine (single source of truth, pure TypeScript, no DOM)
- `opal-workflow-layout.js` — compiled ES module output (committed; served as a static asset)
- `opal-workflow-layout.d.ts` — TypeScript declarations for consumers (generated by `tsc`)
- `index.html` — browser tool: UI, styles, imports engine via `<script type="module">`
- `tsconfig.json` — TypeScript compiler config (`target: ES2017`, `module: ES2020`)
- `package.json` — dev dependency on TypeScript; `npm run build` compiles the engine
- `application.md` — full application spec

Connected to GitHub — every push to `main` auto-deploys via Cloudflare Pages.
No build step on deploy (compiled `.js` is committed). Build output directory: `.`

## To deploy changes

### Engine changes (`opal-workflow-layout.ts`)
1. Edit `opal-workflow-layout.ts`
2. Run `npm run build` — regenerates `opal-workflow-layout.js` and `opal-workflow-layout.d.ts`
3. Commit both `opal-workflow-layout.ts` and `opal-workflow-layout.js`
4. Push to `main` — Cloudflare deploys automatically

### UI-only changes (`index.html`)
1. Edit `index.html`
2. Commit and push to `main` — Cloudflare deploys automatically
